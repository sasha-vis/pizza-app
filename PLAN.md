# PLAN.md — дорожная карта «Пицца Феникс» (`pizza-app`)

Интернет-магазин пиццы (доставка в Минске): каталог, корзина, оформление
заказа с записью заявки в БД. Этот файл — живая карта: сверху история по фазам,
снизу — что делаем дальше.

## Стек (текущий)

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind v4 · Zustand 5 ·
Supabase (Postgres) · деплой на Vercel + Supabase. Детали кода — в `CLAUDE.md`.

**Целевая архитектура — Feature-Based** (код по фичам: `features/*` + `shared/`,
`app/` — только роуты). Переход — Фаза 3.

---

## Сделано

### `v1` — оригинал (2021)

- CRA / React 17, react-router-dom v5, react-slick.
- Чистый фронтенд: без бэка, БД, TypeScript и менеджера состояния.
- Корзина — JSON-строка в localStorage (ключ `cart`). Деплой на GitHub Pages.
- Перед миграцией на Next был короткий промежуточный шаг на Vite.

### Фаза 1 — миграция на Next.js (→ часть `v2`)

- CRA/Vite → **Next.js 15 (App Router)**, React 19, **TypeScript** (strict).
- Роутинг: `BrowserRouter` → файловый (`/`, `/cart`).
- Корзина: Context + JSON-строка → **Zustand** с `persist` (ключ `cart-v2`);
  убраны чтение `data-*` из DOM и хрупкая логика `CartAdd`.
- 8 почти одинаковых `ProductsComponents` сведены в один серверный `ProductList`
  (интерактив — в клиентском `AddButton`).
- react-slick → **embla-carousel-react** (совместимость с React 19).
- Tailwind v4 подключён; основная вёрстка — на перенесённом 1:1 CSS.
- ESLint 9 (flat) + Prettier. Удалены артефакты Vite/CRA.
- Деплой на **Vercel** (GitHub Pages и ветка `gh-pages` удалены).

### Фаза 2 — заказы в Supabase (→ `v2`)

- Подключён **Supabase** (`@supabase/supabase-js`), клиент в `lib/supabase.ts`.
- Таблица **`orders`** (`name, phone, address, items jsonb, total, status`),
  **RLS**: роль `anon` — только `INSERT`.
- `OrderPopup` пишет заявку в БД (`lib/orders.ts`) + валидация полей формы;
  заглушка submit заменена реальной записью. Заявки видны в Supabase Studio.
- Env-переменные `NEXT_PUBLIC_SUPABASE_*` — в `.env.local` и на Vercel
  (Production + Preview).

### Рефакторинги после Фазы 2

- **Единый источник категорий**: `CATEGORIES` (`as const`) в `lib/products.ts`
  несёт ключ, `listClassName` и данные секции; `CategoryKey` выводится типом
  (ручной union из `types.ts` удалён); `SECTIONS` собирает секции главной
  (4 списка закусок — под одним заголовком), `app/page.tsx` рендерит их циклом.

## Дальше

Основной функционал готов и задеплоен. Порядок следующих фаз:
**архитектура → данные → Tailwind → админка → Storybook/PWA**. Архитектура —
первой: TanStack Query, админка и новые фичи должны ложиться уже в
feature-based структуру, а не переезжать потом. Детали уточняются перед началом
каждой фазы.

### Фаза 3 — Feature-Based архитектура

Цель: перегруппировать код по фичам вместо технических слоёв
(`components/`, `lib/`). Поведение не меняется — чистый structural refactor.

Целевая структура (ориентир, уточнить при старте):

```
app/                    # только роуты и layout (тонкие, собирают фичи)
features/
  catalog/              # витрина: ProductList, products.ts (CATEGORIES,
                        # SECTIONS, getProducts...), types (Product)
  cart/                 # корзина: store.ts, CartList, AddButton,
                        # useHydrated, селекторы
  checkout/             # оформление: OrderPopup, orders.ts (createOrder)
shared/
  components/           # Nav, Slider, ScrollTopButton (общий каркас/лейаут)
  lib/                  # supabase.ts, общие утилиты
data/                   # products.json, images.json (до переезда в БД, Фаза 4)
```

- [ ] Зафиксировать правила слоёв: `features/*` не импортируют друг друга
      напрямую (кросс-фичный интерфейс — через публичный `index.ts` фичи);
      `shared` не знает о фичах; `app/` — только композиция.

      публичного API `cart`), `useHydrated` (`shared` или `cart`).
- [ ] Перенести файлы, завести `index.ts` (public API) у каждой фичи, обновить
